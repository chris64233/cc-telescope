# cc-telescope

管理观测提案、仪器需求和台站时间，并支持**目标机会观测（Target of Opportunity, ToO）对普通观测计划的受控抢占**。

## 主要业务规则

### 基础预订

- **望远镜与仪器**：望远镜登记唯一编号、名称、支持的仪器集合，以及固定的仪器切换准备时长（分钟）。
- **获批提案**：提案登记唯一编号、允许使用的仪器集合和总观测分钟配额；配额随预订扣减、随取消归还。
- **观测预订**：预订关联提案、望远镜、仪器和起止时间（ISO-8601，左闭右开 `[start, end)`，需对齐整分钟）。
  仪器必须同时被望远镜支持且被提案允许；预订时长从提案剩余配额中扣减，配额不足时拒绝。
- **时间冲突**：同一望远镜上的有效（ACTIVE）预订不得重叠。相邻预订使用不同仪器时，两者之间必须至少留出
  切换准备时长；使用相同仪器时可以首尾相接。新预订会同时检查前、后相邻记录。
- **幂等预订**：每笔预订携带幂等键。相同内容重放返回原预订（HTTP 200），相同幂等键但内容不同返回冲突（HTTP 409）。
- **取消**：仅尚未开始的 ACTIVE 预订可以取消，取消只归还一次配额（重复取消幂等）；已开始或已结束的预订取消返回冲突。
- **并发**：所有写日程的事务按统一顺序加悲观行锁（**望远镜行 → 配额账户行（普通/机会提案，按类型+ID 全局排序）→ 预订行**），
  且预订实体的首次加载即为加锁读取（避免无锁预读进入持久化一级缓存后使 `FOR UPDATE` 读到陈旧状态），
  并发下不会超卖配额、形成时间冲突、产生跨望远镜死锁或重复归还/消费分钟数；状态变更与配额变动在同一事务边界内提交。
- **查询**：`GET /api/telescopes/{code}/schedule` 返回按开始时间升序（再按 ID 升序）稳定排序的有效预订；
  `GET /api/proposals/{code}/quota` 返回提案总额度、已用与剩余分钟数。

### 目标机会提案与受控抢占

- **机会提案**：登记唯一编号、**优先级**（整数，越大越高）、**响应时限**（deadline，新观测的结束时间不得晚于它）、
  **允许仪器集合**和**可用分钟配额**。机会提案有独立的分钟配额账户。
- **机会预订**：抢占成功后建立的新预订，属于机会提案账户、带优先级，出现在望远镜日程中。
- **抢占申请（试算）**：给出机会提案、望远镜、仪器和**期望区间** `[start, end)`，系统计算并返回：
  - 与期望区间重叠（含被仪器切换时间波及）的全部**被影响预订**及其快照（归属、仪器、时长、是否可抢占）；
  - **前、后仪器切换时间**：相邻预订与期望区间使用不同仪器时所需的切换分钟数，以及当前空闲间隔是否满足；
  - 可行性结论与全部冲突原因。试算**不落库、不改变日程与配额**。
- **确认抢占（一次性原子提交）**：
  - 可抢占：**一次性**取消全部被覆盖的可抢占预订、归还各自配额（普通预订→普通提案；
    被更高优先级覆盖的机会预订→原机会提案），扣减本机会提案配额并建立新机会预订；
  - **全部或不做**：存在不可抢占任务、仪器不兼容（望远镜不支持或提案不允许）、期望区间晚于响应时限、
    或机会配额不足时，**原日程与配额完全不变**，仅落一条 REJECTED 记录保存原因；
  - **可抢占判定**：普通预订总可被机会抢占；机会预订仅在申请提案优先级**严格更高**时可被抢占
    （相同或更低优先级不可抢占）。
- **待重排与重排**：
  - 普通预订被抢占后进入 `PENDING_RESCHEDULE` 状态（不占用日程、配额已在抢占时归还）；
  - 可在**同一机会提案的响应时限内**寻找新时段，调用重排接口建立新普通预订；
    **重排成功才再次扣减配额**，冲突/配额不足/超期则保持待重排状态、不扣配额；
  - 重排成功后原预订转为 `RESCHEDULED` 并指向新预订；待重排任务也可直接放弃（取消），但**不会重复归还**；
  - 被抢占的机会预订不参与重排，直接取消。
- **预订状态机**：
  `ACTIVE → CANCELLED`（取消/放弃待重排）、`ACTIVE → PENDING_RESCHEDULE → RESCHEDULED`（被抢后重排）、
  `ACTIVE → CANCELLED`（机会预订被更高优先级抢占）。
- **抢占业务号与幂等**：每次确认携带 `businessKey`。相同业务号内容一致时重放返回原记录（不重复取消/扣减）；
  相同业务号内容不一致返回 409。被拒绝的申请同样占用业务号并重放原拒绝结果。
- **审计与查询**：抢占记录保存**抢占前后日程版本**（望远镜日程版本号每次成功抢占自增）、
  **抢占前后完整日程快照**、**受影响预订快照**、**配额变化明细**和**冲突原因**，可随时查询。

### 天气关闭与受影响观测恢复排期

- **关闭事件登记**：以业务号（`businessKey`）登记某望远镜上的关闭窗口 `[start, end)`（ISO-8601、对齐整分钟）。
  在同一事务内**原子**地：
  - 仅标记窗口内**尚未开始**的有效预订为 `WEATHER_BLOCKED` 并释放其日程占用；**已完成/正在执行的观测保持不变**；
  - 不把分钟退入提案的可消费配额，而是为每条被阻断预订冻结一条**可恢复分钟资格**（`WeatherRecovery`，
    分钟数=原预订时长），资格**保留原归属与优先级**（机会预订保留其优先级）。
- **幂等与范围调整**：
  - 登记以业务号幂等：相同内容重放返回原事件（200），业务号相同但窗口/望远镜不同返回 409；
  - 可调整窗口范围（`POST /api/weather/{businessKey}/adjust`）：**扩大**时阻断新增重叠且未开始的预订；
    **缩小**时把**尚未消耗恢复资格**且落出新窗口的预订恢复回日程（原时段已被其他预订占用或已过开始时间则保持阻断）。
    已部分/全部恢复、已放弃的预订不回退，分钟不重复释放；相同范围重放为幂等空操作。
- **恢复排期**：受影响提案可在原望远镜上为被阻断预订申请新时段（`POST /api/reservations/{id}/recover`）：
  - 新预订**继承原归属与优先级**，**只消耗可恢复资格分钟、不扣减提案配额**；
  - 支持**多次部分恢复**（每次建立一条新预订），资格耗尽时原预订进入 `RECOVERED` 终态并指向收尾新预订；
  - 请求携带幂等键，重放返回原新预订；新时长超过剩余可恢复分钟、仪器不兼容、与有效预订/切换时间冲突、
    或落入仍开放的关闭窗口时**整体回滚，不留下任何部分占用**。
- **放弃（取消）**：
  - 取消被阻断预订：仅把**尚未消耗**的可恢复分钟一次性退还配额账户，资格作废（`FORFEITED`），重复取消幂等；
  - 取消一笔由恢复资格出资的新预订：分钟**退回恢复资格**（而非重复退还配额），若资格由此从终态重开，
    原预订恢复为 `WEATHER_BLOCKED` 可再次申请；
  - 该新预订若被机会观测抢占，同样把分钟退回恢复资格；退回机会/普通账户的规则与普通取消一致。
- **并发安全**：关闭登记、范围调整、取消与恢复排期统一按
  **望远镜行 → 配额账户行（普通/机会，按类型+ID 排序）→ 恢复资格行（按 ID）→ 预订行（按 ID）**
  加悲观锁；同望远镜日程写事务在望远镜行上串行，范围调整/取消/恢复并发时分钟数至多释放或消耗一次。
- **审计与查询**：关闭事件保存当前窗口、**受影响预订快照**（BLOCKED/RESTORED 累积追加）与
  **操作历史**（DECLARED/ADJUSTED 及各自阻断/恢复条数）；恢复详情关联
  **原预订、天气事件、历次新预订与剩余可恢复分钟数**。
- **预订状态机（补充）**：
  `ACTIVE → WEATHER_BLOCKED → RECOVERED`（恢复完成）、`ACTIVE → WEATHER_BLOCKED → ACTIVE`（窗口缩小恢复）、
  `WEATHER_BLOCKED → CANCELLED`（放弃）、`RECOVERED → WEATHER_BLOCKED`（收尾新预订被取消/抢占后重开）。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/telescopes` | 登记望远镜（编号、名称、切换分钟数、仪器集合） |
| GET | `/api/telescopes/{code}/schedule` | 查询望远镜日程（仅有效预订，稳定排序） |
| POST | `/api/proposals` | 登记获批提案（编号、仪器集合、总配额分钟数） |
| GET | `/api/proposals/{code}/quota` | 查询普通提案配额使用情况 |
| POST | `/api/opportunities` | 登记目标机会提案（编号、优先级、响应时限、仪器集合、配额） |
| GET | `/api/opportunities/{code}/quota` | 查询机会提案配额使用情况 |
| POST | `/api/reservations` | 创建普通观测预订（携带幂等键） |
| GET | `/api/reservations/{id}` | 查询预订详情（含状态、抢占来源、重排指向） |
| POST | `/api/reservations/{id}/cancel` | 取消预订；待重排任务则放弃（均不重复归还配额） |
| POST | `/api/reservations/{id}/reschedule` | 将待重排预订安排到新时段（成功才扣减配额） |
| POST | `/api/weather` | 登记天气关闭事件（指定望远镜与窗口，携带业务号，幂等） |
| POST | `/api/weather/{businessKey}/adjust` | 调整关闭窗口范围（扩大阻断、缩小恢复，相同范围幂等） |
| GET | `/api/weather/{businessKey}` | 查询关闭事件（窗口、受影响预订快照、操作历史） |
| GET | `/api/weather/{businessKey}/recoveries` | 查询事件下全部恢复资格（原预订、新预订、剩余分钟） |
| GET | `/api/weather/recoverable` | 查询当前仍可恢复排期（BLOCKED/PARTIALLY_RECOVERED）的资格 |
| POST | `/api/reservations/{id}/recover` | 天气恢复排期（携带幂等键，只消耗可恢复分钟，失败回滚） |
| GET | `/api/reservations/{id}/recovery` | 查询单条恢复详情（原预订、天气事件、新预订、剩余分钟） |
| POST | `/api/preemptions/plan` | 抢占试算：受影响预订、前后切换时间、可行性与原因（不落库） |
| POST | `/api/preemptions` | 确认抢占（携带抢占业务号，幂等；成功 201，拒绝/重放 200） |
| GET | `/api/preemptions/{businessKey}` | 查询单次抢占记录（前后日程、版本、配额变化、冲突原因） |
| GET | `/api/opportunities/{code}/preemptions` | 查询某机会提案的全部抢占记录（含被拒绝申请） |
| GET | `/api/opportunities/{code}/pending-reschedules` | 查询该机会提案下待重排的普通预订 |

确认抢占的响应 `status` 为 `CONFIRMED` 或 `REJECTED`：

- `CONFIRMED`：`scheduleVersionAfter = scheduleVersionBefore + 1`，`opportunityReservationId` 为新预订，
  `quotaChanges` 中正数为归还（`REFUND_PREEMPTED`）、负数为机会消费（`CONSUME_OPPORTUNITY`）；
- `REJECTED`：日程版本前后相同，`opportunityReservationId` 为空，`conflictReasons` 给出全部拒绝原因。

错误以 RFC 9457 `ProblemDetail` 返回：404 资源不存在，409 幂等/时间/取消/重排冲突，422 业务规则校验失败。

天气接口的状态约定：关闭登记/范围调整首次生效返回 201，业务号/相同范围重放返回 200，业务号内容冲突返回 409；
恢复排期首次成功返回 201，幂等键重放（含并发落败后原预订已恢复）返回 200，新时段冲突/落入关闭窗口返回 409，
可恢复分钟不足/仪器不兼容/非原望远镜返回 422。

## 典型流程

1. 登记望远镜 `T1`（CAM/SPEC，切换 30 分钟）、普通提案 `P1`（配额 600）、机会提案 `OP`（优先级 10、
   响应时限、允许 CAM/SPEC、配额 300）。
2. 普通预订：`POST /api/reservations` 在 `T1` 上预订 `P1` 的 CAM 时段。
3. 试算：`POST /api/preemptions/plan` 给出机会期望区间，查看被影响预订与前后切换时间是否满足。
4. 确认：`POST /api/preemptions`（带 `businessKey`）。可行则原普通预订进入待重排、P1 归还分钟、
   OP 扣减分钟并建立机会预订、日程版本 +1；不可行则一切不变，仅记录冲突原因。
5. 重排：`GET /api/opportunities/OP/pending-reschedules` 找到待重排任务，
   `POST /api/reservations/{id}/reschedule` 在响应时限内安排新时段，成功后 P1 再次扣减分钟。
6. 审计：`GET /api/preemptions/{businessKey}` 查看抢占前后日程、版本、配额变化与原因。

### 天气关闭与恢复

1. 登记天气关闭：`POST /api/weather` 指定望远镜 `T1` 与窗口（如次日 09:00–12:00，业务号 `W1`）。
   窗口内尚未开始的有效预订原子进入 `WEATHER_BLOCKED`、释放日程；已开始/完成的观测不变；
   每条被阻断预订冻结等额的可恢复分钟资格（保留原优先级），提案可消费配额不增加。
2. （可选）调整范围：`POST /api/weather/W1/adjust` 扩大则阻断更多预订，缩小则把未消耗资格且落出窗口的
   预订恢复回日程；相同窗口重放幂等。
3. 恢复排期：`POST /api/reservations/{id}/recover` 在原望远镜、关闭窗口之外申请新时段，
   只消耗可恢复分钟（不扣配额），可分多次部分恢复；冲突/超额/落入关闭窗口时整体回滚。
4. 放弃：`POST /api/reservations/{id}/cancel` 取消被阻断预订，仅把剩余可恢复分钟退还一次；
   取消或抢占恢复后的新预订则把分钟退回资格，必要时重开原预订。
5. 查询：`GET /api/reservations/{id}/recovery` 与 `GET /api/weather/W1/recoveries`
   关联查看原预订、天气事件、历次新预订与剩余可恢复分钟数。

## 开发环境

- JDK 21

- H2

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test

测试覆盖：基础预订/取消/配额、抢占试算与确认（成功、优先级阻挡、仪器不兼容、配额不足、超期）、
业务号幂等（确认/拒绝/重放）、待重排与重排（成功扣减、失败不扣、超期拒绝）、以及并发下
取消/抢占不重复归还、重排不重复消费、同业务号只生效一次等场景。

天气关闭与恢复排期另由 `WeatherServiceTest`（23 例）与 `WeatherApiTest`（3 例）覆盖：
关闭仅阻断未开始观测且保持已开始观测不变、关闭登记/范围调整业务号幂等、扩大阻断/缩小恢复、
原时段被占或已部分消耗时不回退、恢复保留原优先级且只消耗可恢复分钟（支持部分恢复）、
超额/时间冲突/落入开放窗口失败不留占用、恢复请求幂等、放弃仅退还剩余分钟一次、
恢复新预订被取消/抢占时分钟退回资格并重开原预订、以及并发下**范围调整/取消/恢复不重复释放或消耗分钟数**
（含分钟守恒断言）等场景。
